# 动效规范（AI 知识讲解视频）

> **目标：让视频看起来专业、显贵、难复刻。**
> 核心不是「效果多」，是**精确 + 一致 + 声画同步**。
>
> 令牌在 `templates/tokens.css` 的「动效」段；本文件说怎么用。
> 全部结论来自 `studio/` 的 5 秒探路片实测，不是纸上谈兵。

---

## 零、什么算「高级」，什么算「廉价」

**高级感只有三个来源：**

| 来源 | 具体是什么 | 业余的做法 |
|---|---|---|
| **精确的缓动** | 每条动效都用手调贝塞尔，快起慢收、尾巴拖长 | 默认 `ease-in-out` / `linear`，机械匀速 |
| **错峰编排** | 元素之间隔 60–160ms 依次落位 | 一起淡入 |
| **形状语法统一** | 全片只有 3 条缓动、4 档时长、4 档错峰；线条端点是圆头 | 这里飞入、那里弹跳、风格拼凑 |

**一句话：高级感来自「一致」，不是来自「复杂」。**

**🚫 禁用（廉价感的直接来源）：**

- 粒子、光效、发光、旋转、翻转、花哨转场
- 默认 `ease-in-out` / `linear`
- 所有元素同时出现
- 动画里出现「随机」的位置或时长
- **负数 `z-index`** —— 探路片实测：`.p-cover .hero .mark::after` 的 `z-index:-1`
  会被父级背景整块盖住，**DOM 里有、画面上没有**。lint 会警告，别忽略。

## 一、动效令牌（唯一定义处）

写在 `templates/tokens.css`，**全片只准用这些值**，不要临场写别的数字。

```
时长   --dur-1 160ms   微反馈：强调、指示条
       --dur-2 280ms   常规进场：次要元素
       --dur-3 480ms   大块进场：标题、卡片
       --dur-4 900ms   生长：线条、遮罩大扫

缓动   --ease-in    cubic-bezier(0.16, 1, 0.3, 1)     快起慢收，进场默认
       --ease-pop   cubic-bezier(0.34, 1.4, 0.64, 1)  轻回弹，仅用于强调
       --ease-line  cubic-bezier(0.65, 0, 0.35, 1)    对称，线条生长

错峰   --stagger-1 60ms   密集列表
       --stagger-2 90ms   常规列表
       --stagger-3 120ms  要点条目
       --stagger-4 160ms  大块之间

气口   --scene-gap 120ms  场景切换后，第一个元素延迟这么久再动
```

**GSAP 里对应写法**（GSAP 不读 CSS 变量，值写死在脚本里，但**必须和令牌一致**）：

| 令牌 | GSAP |
|---|---|
| `--ease-in` | `"expo.out"` |
| `--ease-pop` | `"back.out(1.4)"` |
| `--ease-line` | `"power2.inOut"` |

## 二、五个已跑通的原语

探路片里五个都验证过，直接抄。

### 1. 遮罩揭示（替代淡入，最显功底）

文字从下往上「刷」出来，而不是渐变出现。

```html
<span class="mask"><span class="mask-i" id="t1" data-layout-allow-overflow>提示词是一次性的</span></span>
```
```css
.mask   { display: block; overflow: hidden; }
.mask-i { display: block; }
```
```js
tl.fromTo("#t1", { yPercent: 115 }, { yPercent: 0, duration: 0.7, ease: "expo.out" }, 0.25);
```

> `data-layout-allow-overflow` 是给 check 的说明：这个「溢出」是遮罩动画的**故意行为**，
> 不加会报 info 级 `container_overflow`。

### 2. 线条生长（你特别要的那类）

```css
#rule {
  display: block;          /* 必须 block —— scaleX 对 inline 是空操作 */
  width: 100%;             /* 必须有真实宽度，宽度为 0 就什么都看不见 */
  height: 10px;
  background: var(--brand-500);
  border-radius: 5px;      /* 圆头，细节显贵 */
  transform-origin: left center;  /* 写在 CSS 合法，它不是 transform */
}
```
```js
tl.fromTo("#rule", { scaleX: 0 }, { scaleX: 1, duration: 0.45, ease: "expo.out" }, 0.95);
```

**用法**：分割线、下划线、连接线、指示条、时间轴轨。**每 8 秒至少出现一次。**

### 3. 错峰入场

```js
tl.fromTo(".p-item", { y: 28, opacity: 0 },
  { y: 0, opacity: 1, duration: 0.5, stagger: 0.12, ease: "expo.out" }, 1.3);
```
`stagger` 按列表密度选（`--stagger-1..3`）。

### 4. 底色扫过（关键词高亮）

```html
<span class="kop"><span class="kop-fill"></span><span class="kop-t">你的电脑</span></span>
```
```css
.kop      { position: relative; display: inline-block; }
.kop-fill { position: absolute; inset: 4px -8px; background: var(--brand-200);
            border-radius: 8px; transform-origin: left center; }
.kop-t    { position: relative; display: block; }  /* 后出现的定位元素盖在上面 */
```
```js
tl.fromTo("#hl .kop-fill", { scaleX: 0 }, { scaleX: 1, duration: 0.4, ease: "power2.inOut" }, 2.35);
```

> 用「绝对定位的填充块 + `scaleX`」，**不要**去动 `background-size` 或渐变位置——
> 那些不在可动画属性白名单里。

### 5. 字幕入场

```js
tl.fromTo("#sub", { y: 22, opacity: 0 }, { y: 0, opacity: 1, duration: 0.4, ease: "expo.out" }, t);
```

## 三、声画同步（这是抄不走的那部分）

**别人能抄走单个效果，抄不走「声到画到」** —— 因为它需要词级时间戳。

数据来源：`studio/videos/<片子>/captions.json`（由 `scripts/align.py` 产出）

```json
{ "scenes": [ { "n": 1, "start": 0.0, "end": 4.94, "captions": [ … ] } ],
  "captions": [ { "text": "同一件事，你跟 AI 说过多少遍了？", "start": 0.0, "end": 2.3 } ] }
```

**规则：**

1. **场景时长 = `scene.end − scene.start`**，不是估的、不是我定的
2. **场景内元素的出现时刻，对齐到该场景字幕的 `start`**，而不是场景起点
3. **念到关键词的瞬间，画面上的对应元素亮起来**（`--dur-1` + `--ease-pop`）
4. **场景末尾留 0.3–0.5s 静止**，不要话音未落就切走；`captions.json` 里句子之间的间隙就是天然气口

## 四、场景设计契约

### 4.1 内容必须铺满整帧（探路片踩到的坑）

图文卡片是给静态图设计的，内容**顶部对齐**，中部一大片空。
**视频里这就是几秒钟的死区。** 已确认的解法：

```css
.scene .card { flex: none; justify-content: center; }
```

但居中只是兜底。**每个场景在动手前要先想清楚：这一屏靠什么撑满？**
对比栏、图解、编号、进度指示都可以，但**不能靠留白**。

### 4.2 压缩 ≠ 抽象化（实测踩过，很容易犯）

「画面不复述字幕」**不等于**「画面不要信息」。第 5 章第 1 条的场景 2 就压过头了：

| | 做法 | 结果 |
|---|---|---|
| ❌ **压过头** | 四行灰色占位条 + 「第 1 次…第 4 次」 | 画面**零信息**，观众不知道在讲什么 |
| ❌ **没压** | 把字幕的整句抄到画面上 | 观众读两遍同样的东西，画面白占一个通道 |
| ✅ **正确** | 四个**短标签**：「别写太 AI」「别啰嗦」「按格式来」「要有判断」 | 信息在，但比字幕短得多、可一眼扫完 |

**原则：把句子压成 4–6 字的标签，不是压成灰条。**

**自检（两条都要过）：**

1. **把画面文字全部去掉，观众还能看懂这一屏在讲什么吗？** 不能 → **压过头了**
2. **画面上的每句话，和字幕逐字一样吗？** 一样 → **根本没压**

> 只有**纯装饰/纯隐喻**的图形（进度条、时间轴、母题的复制）才允许没有文字标签——
> 因为它们承载的是"数量/长度/重复"这类**字幕说不出来的信息**。
> 一旦某个图形只是在"占位"，它就是错的。

### 4.3 每个场景必须有「一次线条生长」

线条是质感成本最低、复刻门槛最高的元素。分割线、指示条、连线、下划线都算。

### 4.3 场景切换

- 切完**先静 120ms**（`--scene-gap`）再让第一个元素动。切完立刻动 = 廉价。
- 转场以**硬切**为主，最多用位移推。不要旋转、缩放转场。

### 4.4 焦点要自己走

多条目场景（比如三点差别）：念到哪一条，**那一条上浮 + 左侧指示条生长，其余降权到 `opacity: .55`**。
观众的注意力不该自己找地方落。

## 五、版面契约（1080×1920 · 9:16）

```
┌──────────────────────────┐  y=0
│                          │
│   stage  1080 × 1440     │  ← 复用图文的 .card（原尺寸，一个像素不改）
│   （内容垂直居中）        │
│                          │
├──────────────────────────┤  y=1440
│   字幕带（480 高）        │
│   ▸ 字幕落在这里          │  ← 距底 320px 以上
│                          │
│   ⚠ 底部约 200px 是       │
│     小红书播放器 UI        │  ← 任何内容都不要进去
└──────────────────────────┘  y=1920
```

- **字幕字号 56px 左右**，单行；太长就自己切成两条字幕，别让它自然折行折在奇怪的地方
- **字幕不做逐字卡拉OK高亮**——知识类视频里那是干扰。字幕负责「读」，画面负责「看」，信息通道分开
- 卡片的外围底色和整帧底色都是 `--bg`，视觉上是连续的

## 六、工程契约（HyperFrames）

### 6.1 架构：一个场景一个文件

```
studio/
├── index.html                     ← root：只放场景轨道与全局时间轴
├── compositions/scene-1.html      ← 每个场景一个 sub-composition（<template> 包裹）
├── compositions/scene-2.html
└── ...
```
> lint 会提示 `nested_structure_needs_subcomposition`：**timeline 元素里不要塞嵌套 div**。
> 探路片是单场景所以塞在一起没问题，正式片必须拆。

### 6.2 设计系统怎么接进来（关键，探路片的头号发现）

**HyperFrames 把资源路径钳制在工程根目录内，`../templates/…` 一律不生效**
（`invalid_parent_traversal_in_asset_path`）。这个失败很阴险：**写法看着正常，渲染出来是没有样式的裸 HTML。**

解法是目录联接，不是拷贝：

```
studio/design  ──junction──▶  templates/
studio/fonts   ──junction──▶  fonts/
```

- composition 里写 `./design/components.css`（不越界）
- `components.css` 内部 `@import "../fonts/fonts.css"` 解析到 `studio/fonts/`，**仍在工程内，合法**
- **设计的唯一出处仍然是 `templates/`，没有第二份拷贝**
- 重建：`node scripts/setup-studio.mjs`（幂等）

### 6.3 硬约束（违反会静默出错）

| 约束 | 说明 |
|---|---|
| 变换元素必须 `display:block` + 有真实尺寸 | `scaleX` 对 inline 是空操作；宽度为 0 的元素缩放后什么都看不见 |
| 不用 `<br>` 强制断行 | 显示型标题每行独立成块是允许的例外 |
| 全屏底色放在 root 的**子元素**上 | 放 root 自己身上，合成时可能被丢掉，整帧变黑 |
| 只在白名单属性上做动画 | `opacity` `x` `y` `scale` `rotation` `color` `backgroundColor` `borderRadius` 和 transform |
| 不要给同一元素同时写 CSS `transform` 和 GSAP 补间 | 两者会打架，lint 直接拒（`gsap_css_transform_conflict`）。初始状态写在 `fromTo` 里 |
| 不用 `Date.now()` / 未播种随机 / 网络请求 | 每帧必须能由时间值单独复现 |
| 不用 `repeat: -1` | 用 `Math.max(0, Math.floor(duration / cycle) - 1)` |
| 每个 `id` 全页唯一 | sub-composition 内部用 `#<composition-id>-<name>` 前缀 |

### 6.4 渲染命令与实测速度

```powershell
cd D:\AI\repository\ai-study\studio
$env:TMP='D:\hf-tmp'; $env:TEMP='D:\hf-tmp'   # ⚠ C 盘只剩约 9 GB，帧缓存必须指到 D 盘
npx hyperframes@0.8.156 check                                    # 门禁
npx hyperframes@0.8.156 render --quality high --workers 2 -o renders/out.mp4
```

| 实测项 | 值 |
|---|---|
| 探路片（150 帧 / 5s，**动效密集**） | **16.5 秒**渲染 |
| 第 5 章第 1 条（2367 帧 / 78.9s，**含长定格**） | **1 分 53.9 秒**渲染，命令总耗时 2.0 分钟 |
| 换算 | **每 1 秒成片约 1.4 秒渲染**；动效密集时约 3.3 秒 |
| 为什么差这么多 | HyperFrames 有**静态帧去重**（`reused N/M frames`）——定格越多越快 |
| workers | **限 2**（i5-8400 / 6 核 / 可用内存约 5.9 GB，每个 worker 一个 Chrome 约 256 MB） |
| 硬件加速 | NVIDIA GTX 1060 被自动识别，走 hardware GPU |
| 设计系统继承 | check 里 `Contrast 27/27 text checks pass WCAG AA` |

**估算渲染时间用 2 秒 / 每秒成片**（保守值），别用 3.3。

### 6.5 视频要整体放大一档（实测踩到）

9:16 是**手机上近距离看的大屏**。图文那套字号与间距（为 1080×1440 静态图调的）放进 1920 的整帧，
第一版渲染出来**内容明显偏小、四周发空**。

解法是在 `.scene .card` 作用域内覆盖令牌，**不动设计系统本身、图文那边完全不受影响**：

```css
.scene .card {
  --fs-2: 118px; --fs-4: 76px; --fs-5: 64px; --fs-6: 52px; --fs-7: 42px;
  --sp-3: 32px; --sp-4: 40px; --sp-5: 52px; --sp-6: 64px; --sp-8: 84px;
}
```

**字幕 62px**（不是图文的 42px）。最长的一句 37 字在 62px 下最多 3 行，
落到距底 330px 以上，不会进播放器 UI 的安全区。

### 6.6 字幕交叉淡入淡出要留缝（实测踩到）

字幕用「入 = caption.start，出 = 下一句.start − 0.2」驱动时，
**淡出时长必须小于 0.2**（用 0.18），否则相邻两句会短暂叠在一起，
check 报 `content_overlap`「Two text blocks overlap and may render unreadable」。

## 七、版面溢出：`info` 级 finding 也必须处理

**实测踩到**：场景 5 两条流程图的末端节点「成品」都向右**溢出了画布**。
`check` 其实报了这条，但标的是 `ℹ info` 级，被当成「不影响观看」放过了——**这是判断失误，不是小瑕疵**。

**规则：**

1. **图示的最右端元素必须落在画布安全区内。** 竖屏 1080 宽，左右各留 `--pad-x`(88px)，
   图示可用宽度 **904px**。节点多、要出画时，先缩间距或减节点，**不要让末端出画**。
2. **只有"故意出画"的元素才可以越界**（例如场景 3 的时间轴条——出画本身就是"无限延续"的表达），
   且必须显式标记 `data-layout-allow-overflow`。
3. **`check` 的 `ℹ info` 不等于"可以放过"。** 下面这三类进了 info 也必须处理：
   - `canvas_overflow` / `container_overflow` —— 内容被切或出画
   - `content_overlap` —— 两块文字叠在一起（字幕交叉淡入最容易触发）
   - `negative_z_index` —— 元素被背景吃掉

> 只有明确判定为**故意行为**（遮罩揭示的溢出、出画的延续条）才允许保留，并加标记说明。

## 八、出片前自检

- [ ] 所有时长/缓动/错峰都来自令牌，没有临场数字
- [ ] 每个场景至少有一次线条生长
- [ ] 场景切换后静了 120ms 才动
- [ ] 每个场景的时长等于 `captions.json` 里的实测值，不是估算
- [ ] 关键词高亮对齐到了词级时间戳
- [ ] 每个场景都铺满了，没有中部死区
- [ ] 字幕没有进底部 200px，没有逐字卡拉OK
- [ ] 全片只有 3 条缓动；没有出现禁用清单里的东西
- [ ] **图示最右端元素在安全区内**，没有非故意的出画（`canvas_overflow` / `container_overflow`）
- [ ] **check 的 `info` 级也逐条看过**，只有明确判定为故意行为的才保留（并加标记）
- [ ] `npx hyperframes check` 0 error
- [ ] 抽帧用 `read_image` 亲眼看过至少封面 + 2 个场景
