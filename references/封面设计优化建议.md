# ai-study Skill 封面设计优化建议

> 基于 x-01 原版封面、重写版封面、wb-ch05 封面的横向对比，以及小红书信息流封面设计规律，提出以下优化建议。

---

## 一、封面横向对比：差距在哪

| 维度 | wb-ch05 封面（Skill 原版） | x-01 原版封面 | x-01 重写版封面 |
|---|---|---|---|
| **钩子标签** | 「用 AI 的都卡过这一步」人群+普遍成立 | 「程序员做的 AI 系统」功能描述，无紧迫感 | 「运营过 2000+ 公众号的程序员」人群+资历 |
| **大数字** | ✅ 「100」独立放大，橙色，占视觉主导 | ❌ 无 | ✅ 「2000」橙色放大 |
| **主标题** | 「遍提示词，AI 还是记不住」 | 「写稿一小时，最累的却是找素材」 | 「个公众号之后，他把找素材这活交给了 AI」 |
| **副标题** | 「把要求存成 Skill：不说第二遍，它每次都照着做。」**承诺句** | 「项目 ai-content：把这串活设成定时任务」**说明句** | 「开源项目 ai-content · 五步定时跑」**说明句** |
| **视觉证据** | ✅ **对比卡**：提示词「说一次就没了」vs Skill「存下来长期复用」——认知冲突极强 | 五步链路（流程展示，平淡） | 五步链路（流程展示，仍偏平淡） |
| **角标** | 「零基础能看懂」+「附五件事模板」利益型 | 「真实界面」+「附部署门槛」形式型 | 「真实界面」+「附部署门槛」形式型 |
| **整体评价** | 数字锚定 + 对比冲突 + 承诺句 = **高点击** | 流程展示 + 说明句 = **偏教程感，点击弱** | 数字锚定有，但对比冲突不足 |

**核心差距**：wb-ch05 用「对比卡」制造了认知冲突（之前 vs 之后），x-01 用「五步链路」只是展示了流程。**对比 > 展示**。

## 二、具体优化建议（按优先级）

### P0 — 视觉证据：对比卡优先于流程展示

**现状**：封面视觉证据默认用 `.chain`（五步链路条），但链路条只是流程展示，不产生认知冲突。

**问题**：
- 五步链路条（抓素材→挖选题→筛定位→出初稿→定时跑）太平铺直叙
- 读者看到流程展示的第一反应是「又要学一套流程」，而不是「这能解决我的问题」
- 对比卡让读者一眼看到「之前痛苦 vs 之后轻松」，点击动机更强

**建议**：

1. **封面视觉证据优先级**（应写进 `references/标题与封面规范.md` §六）：

| 优先级 | 视觉证据类型 | 适用场景 | 冲击力 |
|---|---|---|---|
| **1** | **对比卡**（`.duo`） | 有"之前 vs 之后""错误 vs 正确""手动 vs 自动" | ⭐⭐⭐⭐⭐ |
| **2** | **数据对比条**（新增） | 有具体数字对比（3h → 0min、100 条 → 2 篇） | ⭐⭐⭐⭐⭐ |
| **3** | **大数字块** | 单一大数字锚点（2000、100、90%） | ⭐⭐⭐⭐ |
| **4** | **图解/示意图** | 概念解释（如五维雷达图缩略） | ⭐⭐⭐ |
| **5** | **流程链路条**（`.chain`） | 纯流程展示，无对比关系 | ⭐⭐ |

2. **x-01 如果用对比卡，可以长这样**：

```
┌──────────────┐      ┌──────────────────┐
│  手动找素材   │  →   │   AI 自动收集     │
│  每天 3 小时  │      │   打开后台就有    │
│  翻十几个平台 │      │   26 条已收好     │
└──────────────┘      └──────────────────┘
   灰色虚线框               橙色实心块
   （痛点侧）              （解决侧）
```

3. **对比卡使用场景扩充**（当前只有"提示词 vs Skill"一种）：

| 内容类型 | 对比卡 A 侧（痛点） | 对比卡 B 侧（解决） |
|---|---|---|
| 自动化工具 | 手动做：每天重复 3 小时 | 自动跑：打开后台就有 |
| 效率工具 | 之前：翻 10 个平台找素材 | 之后：一个入口全收好 |
| 学习方法 | 死记硬背：说完就忘 | 存成 Skill：每次照着做 |
| 筛选机制 | 凭感觉选：写了也没流量 | AI 打分：不到 90 不写 |
| 内容产出 | 从空白开始：对着屏幕发呆 | 从初稿开始：审核修改就行 |

### P0 — 新增「数据对比条」组件

**现状**：只有 `.chain`（流程链路）和 `.duo`（对比卡）两种封面视觉证据组件。

**建议**：新增 `.p-cover .bar` 数据对比条组件，用于「数字前后对比」场景。

**设计**：

```css
/* 封面数据对比条：数字 + 箭头 + 数字 */

  display: flex;
  align-items: center;
  justify-content: center;

  border-radius: var(--radius);

  flex: none;

.p-cover .bar .side {
  text-align: center;
}
.p-cover .bar .side .num {
  font-family: var(--font-display);
  font-size: var(--fs-3);
  color: var(--ink);
}
.p-cover .bar .side .num.del {
  color: var(--ink-3);
  text-decoration: line-through;
  text-decoration-thickness: 5px;
}
.p-cover .bar .side .lbl {
  font-size: var(--fs-8);
  color: var(--ink-3);
  margin-top: var(--sp-1);

  font-size: var(--fs-4);
```

**x-01 应用示例**：

```
    手动找素材 3h        →        AI 自动收 0min
    （划掉的大字）                 （橙色大字）
```

或：

```
    1431 条素材        →        2 篇初稿

```

### P1 — 钩子标签升级：从「人群词」到「人群+紧迫感」

**现状**：钩子标签词库（`references/标题与封面规范.md` §六·一）有：
- 人群词：做内容的 / 程序员 / 学生党 …
- 紧迫感词：再不改就晚了 / 趁早 / 别再 …
- 身份+普遍成立：用 AI 的都卡过这一步 / 做内容的都懂

**问题**：
- x-01 原版用了「程序员做的 AI 系统」——这是功能描述，不是钩子
- x-01 重写版用了「运营过 2000+ 公众号的程序员」——是人群+资历，但缺乏「跟我有什么关系」的紧迫感

**建议**：

1. **钩子标签词库扩充**（增加「人群+普遍成立」的组合）：

| 类型 | 示例 | 点击率预估 |
|---|---|---|
| 纯人群词 | 「程序员做的 AI 系统」 | 基准 |
| 人群+资历 | 「运营过 2000+ 公众号的程序员」 | +15% |
| 人群+普遍成立 | 「做内容的都懂」「用 AI 的都卡过这一步」 | +25% |
| 人群+紧迫感 | 「做内容的，再不改就晚了」 | +30% |
| 纯紧迫感 | 「再不改就晚了」 | +20%，但缺人群 |

2. **x-01 钩子标签建议**：
- 原：「运营过 2000+ 公众号的程序员」（人群+资历，12字）
- 优：「做内容的都懂」（人群+普遍成立，6字）或「用 AI 找素材的都卡过」（人群+痛点，10字）

3. **规范补充**：钩子标签**优先用「人群+普遍成立」**，其次「人群+资历」，避免纯功能描述。

### P1 — 副标题改为「承诺句」

**现状**：
- x-01 原版：「项目 ai-content：把这串活设成定时任务」→ 说明句
- x-01 重写版：「开源项目 ai-content · 五步定时跑」→ 说明句
- wb-ch05：「把要求存成 Skill：不说第二遍，它每次都照着做。」→ **承诺句**

**差距**：说明句回答「这是什么」，承诺句回答「你能得到什么」。

**建议**：

| 类型 | 示例 | 效果 |
|---|---|---|
| 说明句（弱） | 开源项目 ai-content · 五步定时跑 | 读者：哦，一个项目 |
| 承诺句（强） | 打开后台，素材选题初稿都摆好了 | 读者：我想打开看看 |
| 承诺句（强） | 把重复的收集交出去，判断留给自己 | 读者：这正是我想要的 |

**规范补充**：副标题必须是「结果承诺」或「价值判断」，禁止纯功能罗列。

---

### P1 — 角标升级：从「形式型」到「数据型/利益型」

**现状角标**：
- x-01：「真实界面」+「附部署门槛」→ 形式型（告诉你这是什么形式）
- wb-ch05：「零基础能看懂」+「附五件事模板」→ 利益型（告诉你能得到什么）

**建议角标分级**：

| 级别 | 类型 | 示例 | 点击率贡献 |
|---|---|---|---|
| **S** | 数据型 | GitHub 200+⭐ / 已实测 30 天 | 极高 |
| **A** | 利益型 | 附三步配置 / 零基础能看懂 / 建议收藏 | 高 |
| **B** | 形式型 | 真实界面 / 附部署门槛 / 图文详解 | 中 |
| **C** | 通用型 | 干货分享 / 建议收藏（泛） | 低 |

**x-01 角标建议**：
- 原：「真实界面」+「附部署门槛」
- 优：「GitHub 200+⭐」+「附三步配置」或「已实测」+「建议收藏」

**规范补充**：角标优先用数据型或利益型，形式型仅在无数据可用时降级使用。

---

### P2 — 大数字呈现方式：从「标题的一部分」到「独立视觉锚点」

**现状**：
- wb-ch05：「100」独立一行，橙色，132px（`--fs-1`），占视觉主导 → ✅ 极好
- x-01 重写版：「2000」在标题中放大，但仍与标题文字混排 → 好，但可更好

**建议**：

1. **大数字独立成块**：像 wb-ch05 那样，数字单独占一行或一个视觉块，与标题分离
2. **增加「核心数据块」组件**：

```css
/* 封面核心数据块：超大数字 + 说明 */
.p-cover .stat {
  margin-top: var(--sp-5);
  display: flex;
  align-items: baseline;
  gap: var(--sp-3);
  flex: none;
}
.p-cover .stat .num {
  font-family: var(--font-display);
  font-size: var(--fs-1);   /* 132px */
  color: var(--brand-600);
  line-height: 1;
}
.p-cover .stat .unit {
  font-size: var(--fs-5);
  color: var(--ink-2);
  font-weight: 700;
}
```

**x-01 应用示例**：

```
        2000
    个公众号之后
    
    他把找素材这活
    交给了 AI
```

或双数据块：

```
    2000      200+
   公众号     GitHub⭐
```

### P2 — 封面构图：增加非对称和视觉焦点偏移

**现状**：所有封面都是「标签→标题→副标题→视觉证据→角标」的纵向居中堆叠，对称构图。

**问题**：对称构图显平，信息流中缺乏「第一眼停住」的锚点。

**建议**：

1. **大数字左移**：像 wb-ch05 那样，大数字「100」偏左，标题「遍提示词，AI 还是记不住」跟在右侧，形成非对称
2. **对比卡非对称**：`.duo` 已经是非对称（0.82fr vs 1.18fr），应优先使用
3. **增加「视觉焦点偏移」设计**：
   - 大数字或核心图形偏左/偏上，打破完全居中
   - 角标放在右下角而非底部居中，增加动线

---

### P2 — 封面底纹：增加辨识度

**现状**：封面（`.p-cover`）使用纯 `--bg`（暖白 #fffbf5）底，与内页一致。

**问题**：信息流中纯暖白底不够跳，容易被划走。

**建议**：

1. **封面增加微弱底纹**：如 wb-ch05 和 x-01 都有的浅网格线（`--line-strong` 1px），这是好的，但可更强
2. **封面顶部或底部增加一条品牌色带**：如顶部 8px 橙色条，增加品牌辨识度
3. **或用深色封面变体**（谨慎）：对于「反常识/争议性」选题，封面可用深色底（`--dark-bg`）形成强烈反差，但需保持整体笔记的一致性

## 五、一句话总结

> **封面的核心任务是「3 秒内让人想点开」**。当前 Skill 的封面设计在「结构规范」上做得很好（标签→标题→副标题→视觉证据→角标），但在「视觉冲击力」上偏弱——流程链路条太平铺直叙，副标题偏说明，角标偏形式。**优化方向：对比卡替代流程展示、承诺句替代说明句、数据型角标替代形式型角标。** 这不是推翻设计系统，是在现有组件基础上增加「冲击力」维度的约束。
