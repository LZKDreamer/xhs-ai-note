# 发布与互动 SOP

> **解决什么问题**：流程原来止于「交付文件」，但小红书正文不能放外链、数字会过期、
> 评论区不经营等于放弃一半流量。本 SOP 覆盖**交付之后、发布前后**的所有动作。
> 交付物里必须包含「发布包」，不只是图文文件。

---

## 一、发布包（第 5 步交付时必须一并给出）

| 项 | 内容 |
|---|---|
| 图文 | `笔记.md` 里的标题、正文、分页稿 + 成品图 |
| **首评预埋文案** | 发布后立即由作者发出的第一条评论（见 §三） |
| **发布前复核清单** | 见 §二，逐项打勾后才发 |
| **目标搜索词** | 这条要占哪个词（来自标题公式映射块的 `目标搜索词`） |

## 二、发布前复核清单（逐项打勾）

- [ ] **时效数字复核**：正文里所有会过期的数字（Star 数、版本号、排名、价格）发布当天重新核一遍。
      拿不准就改写法：「目前 200 star」→「200+ star」；核不了就删
- [ ] **关键词落位**：目标搜索词出现在 ① 正文首行标题 ② 正文前 3 行 ③ 话题标签 三处中的至少两处
- [ ] **可搜索路径**：正文提到项目 / 产品 / 资源时，读者**必须能搜到它**——
      给出「搜什么词、在哪搜」（如「GitHub 搜 CheeMao/ai-content」），通用名要加限定词
- [ ] **收藏引导**：有「能带走的页」时，正文里有一句自然的收藏引导（不生硬、不乞求）
- [ ] **话题标签**：5–8 个，按 **2 大词 + 3 中词 + 2 长尾** 搭配，不全是大词
- [ ] **首评文案已备好**：发布 2 分钟内发出

## 三、评论区运营（发布后的第一个 2 小时）

1. **首评预埋**（发布后 2 分钟内）：
   - 正文不能放外链 → **链接 / 仓库名 / 资源获取方式放首评**
   - 或预埋一个补充问题引导评论方向（如「你们每天最机械的那段活是什么？」）
   - **优先用「争议性提问」**：让评论区"吵起来"的互动率比开放式提问高 3–5 倍。例如「最大的问题是『要自己部署』还是『AI 写的不接地气』？站个队👇」——争议点必须来自原文真实门槛，不编造对立
2. **回复时限**：所有评论 **2 小时内回复**——前 2 小时的互动率直接影响推荐权重
3. **置顶评论**：资源路径或补充信息置顶，不进正文（避免被判定导流）

## 四、发布时段

- 工作日 **12:00–13:00** 与 **19:00–21:00** 双时段各测 2 周，用数据定死一个
- 周末上午对知识内容通常更好
- 定死之后写进本节，不再每次纠结

## 五、发布后登记

发布后把笔记链接登记进 `数据记录表.md`（格式见 `references/数据复盘规范.md`），
24h / 72h 各回填一次数据。**不登记 = 这条白发了**——规范无法自我进化。
