# 标题与封面钩子规范

> **两个来源**
> ① `bigpeng-hot-gzh` 的 7 型标题公式 + 8 个选题模板 + 写法细则 + 失败信号（原文面向公众号信息流，**18–32 字**）
> ② 小红书改造：**封面主标题 ≤ 16 字**、正文首行标题 ≤ 20 字
>
> **公式是槽位，不是语料。** 只借结构，产品名必须换成我们实际在讲的东西。

## 零、本项目哪些公式能用（先看这个）

| 公式 | 能否用 | 硬条件 |
|---|---|---|
| 1 数字清单 | ✅ | N 必须是具体整数，正文真有 N 条 |
| 2 我 + 代价 + 收获 | ⚠️ **只在真做过时用** | 需要真实工作量。**绝不编造「我测了 100 个」** |
| 3 反转结论 | ✅ | 反转必须是正文真能解释机制的，不为反转而反转 |
| 4 速成教程 | ✅ | 写了时长 / 字数，正文体量必须配得上 |
| 5 社会证明 | ⚠️ **只在数字可核查时用** | **绝不编造 Star / 下载量 / 实验样本 / 对比分数** |
| 6 对比站队 | ✅ | 对比要有同一任务，抛弃型要真用过被抛弃的那个 |
| 7 情绪短句 | ✅ **最多 1 条** | 后面必须有干货，否则撑不住点击 |
| 8 概念降维 | ✅ 小红书新增 | 把术语翻成人话 |
| 9 身份场景+结果 | ✅ 小红书新增 | 身份+用X做Y+得到Z；结果必须来自原文，不编造 |

**只有 1 条主选时，优先 3 反转 / 4 速成 / 6 对比 / 8 概念降维。**

## 一、小红书标题的硬规则

| 项 | 规则 |
|---|---|
| 封面主标题 | ≤ 16 字，断成 2 行，**第 1 行必须有信息量** |
| 正文首行标题 | ≤ 20 字（小红书标题就是正文第一行），**同样必须来自标题公式映射块**——可与封面同一条，或用备选公式，**禁止直接使用被否掉的说明书式标签** |
| 首行标题与封面的分工 | 封面走钩子公式（负责点击）；首行在命中公式的前提下**埋入目标搜索词**（负责搜索卡位）。两者可以近似，但首行不能退化成「XX：做 A、做 B、做 C」式功能罗列 |
| 目标搜索词 | 每条笔记定 **1 个**（长尾优先，账号前 30 篇每篇死磕一个），填进标题公式映射块的 `目标搜索词:` 行；埋位要求见 `references/发布与互动SOP.md` §二 |
| 钩子标签 | 8–12 字内**只给人群词或紧迫感**，从 §六·一词库取；**不得只是项目名**（`check-copy.mjs` C15 会拦：钩子标签含主角名且无任何钩子标记 → FAIL）。项目名由副标题承担——**副标题里出现主角名即满足 C2「封面出现主角名」**，钩子标签不必背这个活 |
| 钩子不重复 | 封面主标题、痛点页标题、内页标题之间**不得同义重复**；封面视觉证据不与某一内页整页重复（封面给结果或缩略，完整展开留给内页） |
| 话题标签 | 5–8 个，按 **2 大词 + 3 中词 + 2 长尾** 搭配（结构详见 `references/发布与互动SOP.md` §二） |
| **视频口播钩子** | 和封面主标题**必须是两条不同的话**，但指向同一命题 |
| 数字 | 必须具体：100 遍、5 件事、3 层。**禁止「多个」「一系列」「干货满满」** |
| 身份词 | **是点击开关**：上班族、零基础、普通人、创作者、体制内、电商商家、一人公司 |
| 第一人称 | 「我 / 你」优先于「如何」「关于」 |
| 附赠承诺 | 写了「附模板 / 附清单 / 附提示词」，正文必须有对应物 |
| 禁用 | 震惊、重磅、炸裂、必看；「XX 发布了」「盘点 XX」「关于 XX 的思考」 |

**字数怎么算**：汉字、标点、数字、字母**各算 1**；空格不算；英文按实际字母数（`AI` = 2 字，不是 1 字）。

## 二、7 + 1 型公式（小红书版）

> 每条都要写清「**正文必须兑现什么**」。兑现不了就换公式。

### 1. 数字清单

`身份 + 必装/推荐 + N 个 + 对象`

- 上班族必装的 3 个 AI 技能，配一次不用再教
- **兑现**：真有 N 条，每条能装能用，各有一句场景

### 2. 我 + 代价 + 收获

`我用 X 做了 Y（夸张量）+ 得到 Z`

- 我分析了 1000 个 skills，这是最推荐的 30 个
- **兑现**：过程可复述，数字来自真实工作量，结论不是正确废话
- 🚫 **本项目默认不用**：我们没有真实工作量可写，编造即违规

### 3. 反转结论

`以为是 A，其实是 B` / `不是 X，是 Y`

- 你觉得 Codex 不好用，可能是因为它开错了「档位」
- **兑现**：反转要有机制解释，不能只骂一嘴

### 4. 速成教程

`时长或字数 + 精通/速通/保姆级/手把手 + 对象`

- 10 分钟搞懂：为什么你的 AI 记不住你
- **兑现**：按顺序真能跟着做完；写了「避坑/提示词」就必须有独立段落

### 5. 社会证明

`Star / 下载 / 大厂 / 热榜 + 对象 + 它干成了什么`

- **兑现**：数字公开可查
- 🚫 **本项目默认不用**：没查到公开数据就不许写

### 6. 对比站队

`A 和 B 到底选哪个` / `实测 A 和 B` / `彻底抛弃了 X`

- 提示词和技能到底差在哪？同一个任务我试了两遍
- **兑现**：同一任务、可对比的维度、明确站队（不分场景和稀泥）

### 7. 情绪短句

短、口语、带情绪（慌 / 杀疯了 / 拉完了 / 有福了 / 卷到）

- 跟 AI 说了一百遍，它还是不懂我
- **兑现**：后面必须有干货
- **默认只出 1 条**

### 8. 概念降维（小红书新增）

把专业词翻成一句人话

- 提示词是一次性的任务，技能是能存下来的做法
- **兑现**：翻完之后读者能拿去跟别人复述

### 9. 身份场景 + 结果（小红书新增）

`身份 + 用 X 做 Y + 得到 Z`

- 程序员把周报丢给 AI，10 分钟下班
- **兑现**：身份按内容推断**一个**（正文按该身份写场景）；结果必须来自原文，**不编造**「10 分钟」若无依据
- 适用：原文有明确使用者 + 明确产出，又不属于反转 / 对比时

## 二·四、组合公式（允许叠加，最多 2 型组合）

> 单一公式有时不够有力，允许把 2 个公式叠加成一条标题，但**必须能拆回各自的骨架**，不能变成四不像。

**可用组合**：

| 组合 | 骨架 | 示例 |
|---|---|---|
| **社会证明 + 反转结论** | `[资历/数字] + [痛点] + [交给AI/解决方案]` | 2000 个公众号之后，他把找素材这活交给了 AI |
| **数字清单 + 速成教程** | `[N 步] + [时长] + [精通/搞懂] + [对象]` | 5 分钟搞懂：AI 内容系统的 5 步流水线 |
| **身份场景 + 对比站队** | `[身份] + [抛弃 A 拥抱 B]` | 运营过 2000 个号的人，为什么抛弃了手动找素材 |
| **反转结论 + 速成教程** | `[反常识] + [N 分钟搞懂]` | AI 记不住你，3 分钟搞懂为什么 |

**组合规则**：
- 最多 2 型组合，3 型及以上会混淆信息焦点
- 组合后字数仍要满足封面 ≤16 字、首行 ≤20 字
- 两个公式的「兑现」都要在正文里有对应页
- 标题公式映射块的 `公式:` 字段写主公式 + 次公式，如 `公式: 社会证明 + 反转结论`

**自检**：把标题拆成两部分，每部分都能独立对应一个公式骨架 → 组合成立；拆不开 → 重写。

## 二·五、标题公式映射（**必填，脚本会拦**）

> **不填这一段，`scripts/check-copy.mjs` 直接判不合格。**

第 14 轮的教训：这一页有 8 型公式、每条都写了「正文必须兑现什么」，
**但我写的两个封面标题一个都没命中**——因为它们不是公式产物，是我临场编的描述句。
所以现在**先把公式选出来、把槽位填满，再写标题**，并把这四行留在 `笔记.md` 里：

````markdown
**标题公式映射**（`scripts/check-copy.mjs` 会校验这一段）

```text
公式: 反转结论
骨架: 不是 X，是 Y
标题片段: 最累的不是写，是每天从零找素材
X: 写稿那一小时
Y: 每天从零找素材
目标搜索词: AI自动写稿
兑现: 第 02 页把「从零」拆成四个具体动作；第 03 页给出系统的五步
```
````

| 字段 | 要求 | 脚本怎么查 |
|---|---|---|
| `公式` | 必须是 §二 里那 9 型之一 | 名称必须命中白名单 |
| `骨架` | 这一型的句式骨架 | 非空 |
| `标题片段` | **封面主标题里的一段原话** | C5：必须是 `笔记.md` 封面主标题的字面子串；C9：必须也出现在 `note.html` 的封面里 |
| `X` | 反转/对比型公式里被否定的那一端（"不是 X"中的 X） | **C16：X 字段任意 ≥2 字连续子串必须出现在「标题片段」里**——防"声明 X=写稿那一小时、封面却写最累的不是写"的盲区 |
| `Y` | 反转/对比型公式里被肯定的那一端（"是 Y"中的 Y） | **C16：Y 字段同理** |
| `目标搜索词` | 这条要占的 1 个搜索词（长尾优先） | C13：必填；且必须出现在正文首行标题或正文前 3 行 |
| `兑现` | 正文哪一页兑现了这个承诺 | 人看 |
| `评分`（可选） | 六维加权评分（见 §二·六），主选 = 最高分 | W6：填了则校验格式；未填只提醒 |

**为什么 `标题片段` 要卡这么死**：它同时防两件事——
① 声明的是 A 公式、写出来的是 B 句子；
② 改了标题却只改了 `笔记.md`、页面上还是旧的那句。

## 二·六、六维加权评分（主选 = 最高分）

> 现在主选标准只有一句"优先 3 反转 / 4 速成 / 6 对比 / 8 概念降维"——不够。出 1 主 + 3 备后，按六维给每条打分（0–5），加权总分最高者为主选。发布后用真实数据（点击率/收藏率）校准权重。

| 维度 | 权重 | 怎么打分（5 分制） |
|---|---|---|
| 主题匹配度 | ×3 | 标题与正文命题是否一致；偏离 = 0–1 |
| 结构合规度 | ×2 | 是否命中 9 型公式且槽位填满；没命中 = 0 |
| 利益清晰度 | ×2 | 读者能不能 3 秒看出"我能得到什么"；只有代价没结果 = 1 |
| 情绪唤醒度 | ×2 | 有无冲突/反常识/紧迫感；通稿体 = 1 |
| 稀缺性感知 | ×1 | 读者觉得"别处看不到"；正确废话 = 1 |
| 合规安全性 | ×2 | 无禁用词、无编造数字、无误导；踩线 = 0 |

**写法**（填进映射块的 `评分` 行，可选）：

```text
评分: 主题4×3 利益5×2 情绪3×2 稀缺2×1 合规5×2 = 39/50
```

复盘回流：把"高分标题却数据差"的案例记进 `爆款标题档案.md`，反过来调权重。

## 三、写法细则

- **工具名尽量出现在前 16 字**：信息流截断后仍能看懂在讲谁
- **关键信息前置 8 字**：数字 / 身份词 / 冲突词尽量落在标题前 8 字——feed 流会压缩封面，主标题第 1 行才是黄金位（wb-ch05 复盘：数字前置后冲击力更强）
- **第 1 行就要是完整命题，不能只是否定句半边**：信息流截断后读者只看到第 1 行就要能懂在讲什么。"不是 X"算半句——读者会问"不是 X 什么？"；要补到"不是 X 动作"才算完整。
  - ❌ 反例：「最累的不是写，是每天从零找素材」——第 1 行"最累的不是写"，"写"太抽象，读者问"写什么？写代码？写稿？"话没说完
  - ✅ 正例：「写稿一小时，最累的却是找素材」——第 1 行"写稿一小时"已是完整命题（动作+量化），截断后仍能看懂
  - 校验：W1 启发式判定——标题第 1 行（断行后或前 8 字）必须含具体动作或完整主谓，不只是孤立否定词

## 三·一、原文数字钩子优先保留

> 原文里如果有具体数字（X 小时 / X 倍 / X 个 / X star / X 人 / X 篇 / X 年），标题作钩子时**必须保留原数字**，不得抽象化、不得为字数压缩而省略——数字是爆款最强的单一钩子，丢了等于丢了钩子。

**为什么这条**：x-01 原文第 5 行原话是「做内容最消耗的，往往不是**写稿那一小时**」——数字 + 动作俱全。生成时却把"写稿那一小时"缩成抽象的"写"，丢了原文给的现成数字钩子，标题立刻弱下来——这是个不该犯的错。

**校验方式**：脚本无法机械判定"原文有数字被丢"（要看原文+映射块的对照），靠自检清单 + 兑现字段注明出处。

**自检**：
- [ ] 原文里出现的具体数字，标题作钩子时是否原样保留？
- [ ] 映射块 `X` / `Y` 字段里如果有数字，标题片段里是否同样出现该数字？

## 三·二、（保留扩展位）
- **数字要具体**：7、10、50、209 页、3.5 万 Star —— 禁止「多个」「一系列」
- **第一人称优先**：「我用 / 我让 / 我把 / 亲测」通常优于「如何如何」
- **身份词是点击开关**：缺身份时可以补，但**只补一个**，且正文要按该身份写场景
- **口语 > 书面**：档位、杀疯了、有福了、卷到 —— 但**禁止空喊**震惊、重磅、炸裂、必看
- **附赠括号是履约承诺**：`（附提示词）` `建议收藏` —— 标题写了，正文必须有对应物
- **不要为了具体而编造**：具体化必须来自真实或**普遍成立**的事实。
  ❌「上周你跟 AI 说过的那句话」（为什么是上周？编的）
  ✅「同一件事，你跟 AI 说过多少遍了？」（普遍成立）

## 四、缺元素时怎么补

从内容里抽：对象、身份、数字、结果、冲突、代价、附赠物。

| 缺什么 | 可以补 | 不可以补 |
|---|---|---|
| 身份 | 按内容推断**一个**，并标注需兑现 | 同时堆三个身份 |
| 数字 | 用正文里真实可数的条数；没有就改用不依赖数字的公式 | 编造 Star、下载量、实验样本量 |
| 结果 | 用已有的结论收紧 | 发明没做过的「反超 8.7 分」 |
| 附赠 | 仅当确实会提供教程 / 提示词 / 清单 | 空挂「附完整教程」 |

## 五、8 个选题模板

高转化选题同时满足三件事：**具体对象 + 可感知结果 + 读者身份或情绪**。
只有热点没有用法，或只有教程没有钩子，都偏弱。

| # | 模板 | 何时用 | 槽位 | 正文要兑现 |
|---|---|---|---|---|
| 1 | 必装清单 | 有一组可执行物 | 身份 + N 个 + 对象 | 真有 N 条，每条有场景 |
| 2 | 亲测复盘 | 做过够夸张的实验或批量分析 | 我用 X 做了 Y + 得到 Z | 过程可复述，数字真实 |
| 3 | 从 0 到 1 教程 | 读者不会用、刚听说 | 门槛 + 手把手 + 对象 | 跟着做完；避坑要有独立段落 |
| 4 | 热点产品落地 | 新功能发布 24–72h 内 | 产品名（前 16 字）+ 玩法数 + 附赠 | 至少一种可复现玩法，禁复述发布会 |
| 5 | 对比抉择 | 两个概念/工具被混用 | A 和 B 到底差在哪 | 同一任务 + 明确站队 |
| 6 | 开源神器安利 | 有硬社会证明 | Star/下载 + 它解决的一件具体事 | 数字可查 + 一个真实用例 |
| 7 | 身份场景化 | 工具不新，但接到具体岗位就成新选题 | 身份 + 用 X 做 Y | 场景细节要像那个身份真会遇到的 |
| 8 | 反常识 / 情绪钩 | 能挑战读者正在做的事 | 你以为 A，其实 B | 反转要给机制，不能只骂一嘴 |

**映射提示**（内容像什么 → 优先哪个模板）：

| 内容像什么 | 优先模板 |
|---|---|
| 推荐、必装、合集、N 个 | 1 必装清单 |
| 我测了、踩坑、复盘 | 2 亲测复盘 |
| 不会用、教程、从 0 到 1、接入 | 3 从 0 到 1 教程 |
| 刚发布、终于来了 | 4 热点产品落地 |
| A 还是 B、对比、容易被混用 | 5 对比抉择 |
| GitHub、Star、开源、替代 XX | 6 开源神器安利 |
| 电商 / 体制内 / 上班族 / 一人公司 | 7 身份场景化 |
| 吐槽、误区、反直觉、坏习惯 | 8 反常识 / 情绪钩 |

## 六、封面设计规则（吸睛的关键）

封面必须同时做到三件事，缺一个就不合格：

1. **3 秒内看懂讲什么** —— 主标题就是结论或冲突，**不能是悬念句**
2. **有视觉证据** —— 对比卡 / 数字 / 图解，不能只有字
3. **有理由点开** —— 钩子标签（人群词或普遍成立的紧迫感，如「用 AI 的都卡过这一步」）+ 附赠承诺（「附清单」）
   > ⚠️ 钩子标签里的数字必须**可核查或普遍成立**：禁止无出处的百分比（「90% 的人卡在这一步」属禁例，见 `references/人味写作规范.md` §二）。要紧迫感就用身份词或普遍成立的说法。

### 六·一、钩子标签词库（从词库取，不得临场造）

**人群词**（优先，是点击开关）：做内容的 / 程序员 / 学生党 / 职场新人 / 自媒体博主 / 副业党 / 一人公司主理人 / 用 AI 的人
**紧迫感词**：再不改就晚了 / 趁早 / 别再 / 卡在这一步的人比你想的多 / 早一天少踩一个坑
**身份+普遍成立**（最稳）：用 AI 的都卡过这一步 / 做内容的都懂 / 跟 AI 说过一百遍的都懂

> 词库会随 `references/数据复盘规范.md` 的回流数据迭代。先有词库，钩子标签才不会退化成"报项目名"。

### 六·二、身份词库（标题与钩子通用，按账号定位校准）

账号定位是「已经在用 AI、但没搞明白的人」。可用身份词：
上班族 / 零基础 / 普通人 / 创作者 / 体制内 / 电商商家 / 一人公司 / 学生党 / 职场新人 / 自媒体博主 / 副业党

- **一条标题只补一个身份**，且正文要按该身份写场景
- 缺身份时按内容推断**一个**并标注需兑现；**不同时堆三个身份**

**封面结构（自上而下）**

```
[钩子标签]      橙底白字胶囊，8–12 字，优先人群词或紧迫感，再报项目名
                （有门槛的词不做第一眼：❌「开源项目 · ai-content」→ ✅「程序员做的 AI 系统」，
                项目名移到副标题或内页 eyebrow）
[主标题]        得意黑，96–110px，2 行，第 1 行最有信息量
[副标题]        40–46px，一句给解法（项目名可放这里）
[视觉证据]      对比卡 / 图解 / 数字条（占版面 30–40%，不与某一内页整页重复）
[角标]          2 个胶囊：价值承诺 + 内容形式
```

**视频封面同用这一套。** 视频封面**必须是静止可读的**，不能依赖动效表达信息。

## 八、失败信号（出现即重写）

- `XX 发布了` / `盘点 XX` / `关于 XX 的思考`
- 通稿体、正确废话（「AI 正在改变我们的工作方式」）
- 震惊、重磅、炸裂、必看
- 「多个」「一系列」「干货满满」
- **只有代价没有结果**（「同一个要求你说了 100 遍」—— 然后呢？读者不知道你想说什么）
- 备选之间只改两个字
- 标题写了附教程 / 提示词，兑现点却是空的
- 编造 Star、下载量、实验样本、对比分数
- 为了具体而编造具体时间 / 数量（「上周」「三天前」）
- 封面主标题是悬念句
- 视频口播钩子和封面主标题是同一句话
