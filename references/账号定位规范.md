# 账号定位规范

> **面向读者的一切输出——简介、标题、封面、正文、口播——都以本文件为准。**
> **定位不可变；人设和风格可调，但都不得与定位冲突。**

## 一、三件事分清：定位 / 人设 / 风格

| | 内容 | 可变 |
|---|---|---|
| **定位** | AI 知识博主，带技术小白入门 AI | ❌ 不变 |
| **人设** | 程序员（真实身份） | ✅ 可调 |
| **风格** | 不堆术语、讲人话 | ✅ 可调 |

- **定位**回答「做什么、为谁做」——它是每一个标题和口播稿的主体。
- **人设**回答「你凭什么讲」——它只提供来处，不提供主题。
- **风格**回答「怎么做」——它只做修饰。

### 硬规则 1：人设只能支撑定位，不能替换定位

**判断方法**：说完人设之后，再问一句「那这个号是干什么的」——
答得出来，人设是支撑；答不出来，人设已经吃掉了定位。

> 反例：「职场成长博主」——它描述了处境，没描述内容。读者会订阅处境，而处境会变。

### 硬规则 2：定位 ≠ 风格（本项目踩过的错）

| | 例子 | 问题 |
|---|---|---|
| ❌ 把风格当定位 | 「把 AI 官方文档翻译成人话」 | ① 这是手艺，不是身份；② 把内容源窄化成了「官方文档」，和 `PROJECT.md` 白名单（蓝皮书 / 下载的文章 / 粘贴原文）不符 |

**同一个错会出现在别的地方**：标题写成「我是怎么把文档翻译成人话的」、口播开头自称「我是专门翻译文档的」——
**只要把「怎么做」放在了「是什么」的位置上，就是同一个错。**

> 「翻译成人话」没有被废弃，它只能待在第 3 行当风格说明。

## 二、账号名

### 定名：`Kai讲AI`

| 项 | 值 |
|---|---|
| 账号名 | **`Kai讲AI`** |
| 字体搭配 | `Kai` 用 **Geist Mono**，`讲AI` 用**得意黑**（均已本地化，见 `templates/base.css`） |
| 口播自称 | **`Kai`**（≤ 4 字，符合 `references/口播稿规范.md` 的称呼长度限制） |
| 简称 | 「Kai」——评论区和口播里叫得顺 |

**定名理由**：人格符号（`Kai`）和品类词（`AI`）都在。人格符号负责被记住，品类词负责被搜到。

### 命名规则（改名或做矩阵时复用）

1. **含「AI」**——小白会去搜「AI 入门」「AI 是什么」，名字里焊一个搜索词；且每次被 @、被截图、被口播提到都是一次曝光。
2. **要能被叫出来**——试一下 `@账号名` 顺不顺、能不能简称。评论区叫不顺，传播效率直接减半。
3. **不含**：生造英文、年份（会过期）、「官方 / 学院 / 中心 / 训练营」（易判营销）、第三方品牌名（把号锁死在单一来源 + 合规风险）。
4. **别比定位窄**——名字暗示的范围不能小于定位，否则讲超出范围的内容就别扭。

### 定名前自检（过 6 项再用）

| # | 检查 | 判断方式 |
|---|---|---|
| 1 | 含「AI」 | 搜索入口 |
| 2 | **口播测试** | 念给一个朋友，他能一字不差打出来吗？打错就不能用 |
| 3 | **@ 测试** | 打 `@账号名` 顺不顺？能不能简称？ |
| 4 | 不是在堆搜索词 | 名字描述「你是谁 / 你对谁做了什么」，不是「小白＋AI＋笔记」三个词相加 |
| 5 | 三年后还成立 | 无年份、无热点梗、无「第X期」 |
| 6 | 不撞头部 | 搜一遍同领域，对方粉丝多就换 |
| 7 | 无营销词 | 见上面第 3 条 |
| 8 | 你念出来不尴尬 | 最真实，也最容易被忽略 |

> ⚠️ **用真名片段做账号名 = 账号和生活绑死。** 以后不好切割，任何人（包括雇主、客户）都能把号和你本人对上。
> 内容方向（AI）是加分项，但主页上不能挂负面叙事——见 §六。

## 三、简介

### 定稿

**A. 带年限版（年限待用户确认，未确认前不要填）**

```
N 年程序员｜带 0 基础的人入门 AI
概念讲明白｜工具怎么用｜哪里容易踩坑
一条讲透一个概念，配一张能看懂的图
原文没说的我不写
```

**B. 不带年限版（可直接发布）**

```
带 0 基础的人入门 AI
概念讲明白｜工具怎么用｜哪里容易踩坑
一条讲透一个概念，配一张能看懂的图
原文没说的我不写
```

- **第 1 行只放定位或真实身份**，不放风格、不放处境。
- **第 4 行是立场，不是资历。** 知识号读者的判断标准是「这一篇讲清楚了没有」，
  不是「你什么学历」——所以本项目**不需要「信任状」那一行**。
  用一条**可被读者验证的自我约束**（原文没说的我不写）代替它，更有用。
- 简介有字数上限，**别写满**，留余量给以后加内容。

### 简介里不写什么

| ❌ 不写 | 理由 |
|---|---|
| 商务邮箱 | 现阶段会让人以为你要接单，和「学习交流」定位冲突 |
| 涨粉数 / 更新天数 | 编造风险；且增速慢时是负资产（见 §五） |
| 未经确认为真的资历 | 学历、大厂、头衔——**简介空一行不难看，编一句话很难看** |
| 站外引流 | 微信 / 公众号 / 二维码，平台不允许 |
| 第三方品牌名 | WorkBuddy / 豆包——把号锁死在单一来源，且不合规 |

## 四、主页三件套

| | 做法 | 理由 |
|---|---|---|
| **头像** | 母题里的 **▣ 实心方块**（橙底深字，或米白底橙框） | 母题 ◯→▣ 就是账号符号；头像到封面一条线，主页九宫格天然成一片暖橙 |
| **置顶 1** | **知识地图**：把已讲的概念画成一张图，随更新往里填格子 | 读者会**为了看全图而关注**。直接复用第 08 页的 `▣▣▣▣` 母题 |
| **置顶 2** | 最硬的一篇（第 5 章「什么是 Skill」） | 价值锚 |

**主页九宫格必须同色系。** 视觉统一是「主页看起来像一个号」的主要来源——
不统一的话，16 篇会像 16 个号发的。

## 五、「进度条」的等价物：概念序号

| | 养成系账号（本项目**不采用**） | 本项目 |
|---|---|---|
| 进度条燃料 | 天数 + 粉丝数 | **概念序号** |
| 例 | 「做自媒体第 14 天，粉丝 3000」 | 「第 7 个概念」 |
| 问题 | 燃料是**别人的处境**；进度条只在上升时好看，粉丝少时是负资产；且天数/粉丝数一旦编造就违反 `PROJECT.md` 边界规则 1 | 燃料是**知识地图的完成度**，不受涨粉速度影响，画一格就多一格 |

读者追的是「**这张知识地图还没画完**」，不是「你涨了多少粉」。

## 六、人设边界：不写进去的东西

| 项 | 决定 |
|---|---|
| **个人处境** | **完全不提。** 在职/求职状态、经济状况、家庭情况，一律不进简介、标题、封面、口播稿。 |
| 程序员身份 | 可以说，因为是真的。但句式是「我是程序员，**所以我负责把技术细节跳过**」，不是「我是程序员，所以我懂」——后者会劝退小白 |
| 年限 | 用户确认后才可以写，未确认前用 §三 的 B 版 |

**为什么个人处境不入人设**：

1. **留存**——用处境吸引来的人订阅的是处境，不是知识。处境会变，知识不会。
2. **画像**——被处境吸引来的人和「想搞懂一个概念」的人，动机不同，会把粉丝画像和内容定位拉歪。
3. **转型**——人设和处境绑定后，以后想转成正经知识号，主页历史会拖着你。

> **这个号可以是作品集，不是情绪出口。** 持续产出 AI 内容的账号，需要展示时能直接给人看——
> 前提是主页挂的是「我在讲 AI」。

## 七、期望值（先说清，免得做错判断）

- **不要拿养成系账号的涨粉速度做基准。** 情绪号靠推荐流破圈，知识号靠**搜索与收藏**复购，前 20 篇的粉丝数天然更低。
- 这是**定位决定的，不是内容差**。不要因此回头去模仿养成系——人设和素材都不支持，会两头不靠。
- 判断知识号做得好不好，先看**收藏率**和**搜索来的流量**，不先看粉丝数。

## 八、内容里怎么自称

| 阶段 | 做法 |
|---|---|
| **新号（当前）** | ❌ **不放自我介绍。** 没有认知度，说了也白烧 3 秒 |
| 有粉丝基础后 | ✅ 可放 **`Kai`**，且必须**紧跟钩子**，不能单独占一拍 |
