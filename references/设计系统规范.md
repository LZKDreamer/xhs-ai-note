# 设计系统规范

> 这是本项目的设计系统说明。改任何视觉相关的值之前先读这里。
> 所有约束都可由脚本验证，不靠手感。

## 0. 一句话

**设计系统的价值不在于有配色表，而在于约束可被机器验收。**
本项目把「配色可读性」写成了可执行的检查：`node scripts/contrast.mjs`。

## 1. 三层文件结构

| 文件 | 职责 | 改动频率 |
|---|---|---|
| `templates/tokens.css` | 设计令牌：颜色、字号、间距、圆角、阴影。**唯一出处** | 低，改配色只动这里 |
| `templates/base.css` | 画布 1080×1440、卡片容器、排版原子（`.t-title` `.eyebrow` `.hl`） | 低 |
| `templates/components.css` | 8 种页型组件 | 中，加页型时改 |

约束：`components.css` 里**不允许出现魔法数字**，间距/圆角/字号一律引用令牌。
引入顺序必须是 `fonts.css → tokens.css → base.css`，且 `@import` 只能在文件最前面。

## 2. 色彩系统

### 2.1 核心决策：亮橙底 + 深字

品牌橙有两个候选方案，实测对比度后选定 A：

| 方案 | 对比度 | 结论 |
|---|---|---|
| **A. 亮橙 `#f97316` 底 + 深字 `#12100e`** | **6.77:1** | ✅ 选定 |
| B. 焦糖 `#b45309` 底 + 白字 | 5.02:1 | 备选，观感偏沉稳 |
| ~~C. 亮橙 `#f97316` 底 + 白字~~ | 2.80:1 | ❌ 已否决，正文会糊 |
| ~~D. 亮橙底 + 浅橙字~~ | 2.07:1 | ❌ 已否决 |

A 同时赢两点：对比度更高，且保住了亮橙的视觉冲击力。

### 2.3 硬规则

1. **任何文字颜色都必须落在 `--ink` ~ `--ink-4` 或 `--brand-600/700` 上。**
   不要临时写 `#999`、`rgba(0,0,0,.4)` 这类值。
2. **亮橙 `--brand-500` 上只允许 `--on-brand` 或 `#fff`（大字号）。** 其余一律否决。
3. **改完颜色必须跑** `node scripts/contrast.mjs`，必须 0 组不通过。
   脚本里还记录了「已否决组合」，防止有人顺手改回去。
4. 对比度标准：正文 ≥4.5:1，大字与图形 ≥3:1，纯装饰 ≥1.2:1。

## 5. 字体

| 角色 | 字体 | 权重要求 |
|---|---|---|
| 标题（`--font-display`） | 得意黑 SmileySans | **只有 400**，不要设置 font-weight，会触发合成加粗 |
| 正文（`--font-sans`） | Noto Sans SC | 400 / 700 / 900 可用 |
| 代码（`--font-mono`） | Geist Mono | 400 |

字体全部本地化（`fonts/`），不依赖联网渲染。

## 6. 组件（8 种页型）+ 变体系统

| 页型 | class | 用途 | 关键结构 |
|---|---|---|---|
| 封面 | `.p-cover` | 钩子 + 标题 + 视觉证据 | `.hook` `.hero` `.sub` `.duo` `.cover-foot` |
| 痛点 | `.p-pain` | 扎共情 | `.lead-q` `.stack>.bubble` `.punch` |
| 概念 | `.p-concept` | 讲清一个概念 | `.def` `.rows>.row` |
| 对比 | `.p-compare` | A/B 差异 | `.vs>.col` `.verdict` |
| 清单 | `.p-list` | 收藏点 | `.items>.item>.n` |
| 步骤 | `.p-steps` | 流程 | `.step>.rail>.bub` |
| 截图/代码 | `.p-shot` + `.codebox` | 真实截图或代码 | `.frame` `.mark>.pin` |
| 收尾 | `.p-end` | 判断 + 提问 | `.claim` `.recap` `.ask` |

### 6.1 变体命名与用法

变体统一用 kebab-case 后缀：`sm-dense`（更紧）、`lg-airy`（更松）。**没有变体就是默认密度。**

| 页型 | 变体 | 适用条目数 | 效果 |
|---|---|---|---|
| `.p-list` | 默认 | 3–4 条 | 标题 `fs-6`，描述 `fs-7`，内边距 `sp-4` |
| `.p-list` | `.sm-dense` | 5–6 条 | 标题 `fs-7`，描述 32px，内边距 `sp-3`，序号块 52px |
| `.p-list` | `.lg-airy` | 2–3 条 | 内边距 `sp-5`，序号块 68px |
| `.p-concept` | 默认 | 3 行以内 | 行内边距 `sp-3` |
| `.p-concept` | `.sm-dense` | 4 行以上 | 行内边距 `sp-2` |
| `.p-compare` | 默认 | 每列 ≤4 条 | 列内边距 `sp-4` |
| `.p-compare` | `.sm-dense` | 每列 5–6 条 | 列内边距 `sp-3` |

**实现方式**：每个页型声明一组局部变量（`--dens-pad` / `--dens-gap` / `--dens-num` / `--dens-title` / `--dens-desc`），
变体只覆盖这组变量。**新增变体不需要重写选择器**，加一条变量覆盖即可。

**选择顺序**：先挑合适的变体（作者的判断），再让自动适配兜底（脚本的保险）。
不要指望自动适配去解决「内容本来就该拆页」的问题。

## 7. 自动适配（溢出兜底）

渲染时若某页内容超出可用高度，`render.mjs` 会**自动等比缩小该页**，而不是裁掉。

| 参数 | 默认 | 说明 |
|---|---|---|
| 可用高度 | 1280px | 1440 − 上下内边距（80+80） |
| 缩放下限 | 0.70 | 低于此值字号不可读，宁可报警 |
| 忽略容差 | 1% | 缩放幅度小于 1% 不执行，避免边界抖动 |
| 溢出容差 | 13px | 约 1% 可用高度，视为像素噪声 |

命令开关：

```powershell
# 关闭自动适配（想看真实溢出）
node scripts/render.mjs <html> <out> --no-autofit

# 放宽或收紧下限
node scripts/render.mjs <html> <out> --min-zoom=0.8
```

报告会写明「内容高度 / 可用高度 → 缩放比」，并在缩放低于 90% 时提示精简、触到下限时警告拆页。
**触到下限仍放不下时退出码为 5**，可被 CI 捕获。

### 实现要点（踩过的坑，别改回去）

判定「是否放得下」经历了三次错误尝试，最终方案是**测量时临时解除裁剪**：

| 方案 | 为什么不行 |
|---|---|
| 子元素 `getBoundingClientRect` 求并集 | 页脚有 `margin-top:auto`，自动撑开的空白被算成内容，刚好放下的页被误判为溢出 |
| 子元素 `offsetHeight` 求和 | 同上，弹性子项被撑高后 `offsetHeight` 也包含空白 |
| `scrollHeight − clientHeight` | 在 `zoom ≠ 1` 时不可靠，二分法会卡在下限 |
| **临时 `overflow:visible` 后量真实底边** | ✅ 采用。用「元素相对卡片的偏移」测量，`zoom` 下仍给出正确的 CSS 像素值 |

## 8. 工具脚本

| 脚本 | 作用 | 何时跑 |
|---|---|---|
| `scripts/check.mjs` | **全套验收，一条命令跑完 5 项** | 改完任何东西 |
| `scripts/render.mjs` | HTML → 1080×1440 PNG，含自动适配与溢出检测 | 每次出图 |
| `scripts/lint-tokens.mjs` | 令牌守卫：裸色值 / 内联样式 / 魔法数字间距 | 改 CSS 或 HTML 后 |
| `scripts/contrast.mjs` | 配色对比度审计（WCAG 2.1），含已否决组合回归 | 改任何颜色后 |
| `scripts/probe.mjs` | 诊断：卡片尺寸、溢出、任意元素的计算样式 | 排查样式问题 |
| `scripts/net-probe.mjs` | 诊断：抓取加载失败的资源（CSS/字体为何没生效） | 排查「样式没加载」 |

```powershell
cd D:\AI\repository\ai-study
node scripts/check.mjs          # 全套验收（推荐）
```

**回归基线**：`templates/styleguide.html` 是组件总览，`templates/fit-test.html` 是溢出压力测试。
两者都参与 `check.mjs`，改动设计系统后必须仍然通过。

## 9. 版式铁律

1. **不加页眉页脚**（`.c-head` / `.c-foot` 已废弃并隐藏）：不要系列名、页码、来源标注。
2. **全篇浅色底**，痛点页也用 `--bg`；只有结论条用深色。
3. **不出版面空洞**：偏空的页用 `margin-top:auto` 把末块沉底，或让封面整体垂直居中。
4. **封面必须有视觉证据**（对比卡/图解/数字），不能只有文字。
5. **每页 1080×1440，零溢出**：由 `check.mjs` 保证。
6. **颜色只用令牌**，不写 `#999`、`rgba(0,0,0,.4)` 这类临时值。
7. **样式只写进 CSS**，HTML 里不写内联 `style`（由守卫脚本强制）。

## 10. 换主题

只改 `tokens.css` 里的 `:root` 一组值；或给 `<html>` 加 `data-theme="ink"` 换成深墨蓝主题（已内置）。
换完必须跑 `node scripts/check.mjs`——主题包里的橙色/蓝色互换后，`--on-brand` 与 `--on-ink` 也要跟着改，
否则会出现「深底白字」被误用到新底色上。

## 11. 已知待改进

- `--fs-4` 与 `--fs-5` 在实际使用中偶尔互换，可能只需留一级，说明阶梯还不够贴实际
- 变体只有「密度」一个维度，尚未做「布局类」变体（如清单两栏、对比上下堆叠）
- 自动适配只做整体缩放，没有「优先压缩间距、再缩字号」的分级策略
- 尚未做 3:4 安全区可视化辅助（导出时裁切边界不可见）
- 没有跨页面的一致性检查（例如同一笔记里 `--dens-*` 混用是否合理）
