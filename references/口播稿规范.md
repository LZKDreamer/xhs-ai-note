# 口播稿规范（AI 知识讲解视频）

> **口播稿是视频模式唯一的核心交付物，也是唯一的人工闸门。**
> 它一旦定稿：**时长定了、分镜定了、字幕文字定了**，之后全是机械执行，不再有内容决策。
> **口播稿未经用户确认，不得进入 TTS。**

**语速基准（两次实测，取保守值）**：晓梦 Xiaomeng（`zh-CN-XiaomengNeural`）· 1.20x · +25Hz

| 稿子形态 | 实测 | 样本 |
|---|---|---|
| 单段长句、逗号句读为主 | 6.35 字/秒 | 143 字 → 22.51s |
| **多短句 + 引号冒号 + 分场景（即我们真实的稿子）** | **5.80 字/秒** | 454 字 → 78.89s |

**排稿一律用 5.8 字/秒，不要用 6.35。** 引号「」、冒号、短句末尾、场景之间的换行，
每一次都吃掉一点时间——实测差 9%，足以让一条片子从 72 秒变成 79 秒。

| 目标时长 | 字数（按 5.8） |
|---|---|
| 45s | ~260 |
| **60s** | **~350** |
| **75s** | **~435** |
| 90s | ~520 |

> ⚠️ **估算永远不准。** 口播稿定稿后必须**先出一次音频实测**（`node scripts/tts.mjs`），
> 用 `ffprobe` 读出真实时长并**回填到口播稿的核算表**，再决定要不要删字。
> 换音色或改语速后重新实测，并改掉这张表。

## 零、两条前置铁律（先看这个，写错视角整篇都要重来）

**1. 视角：口播稿是二创，不是解读。**

禁止出现「原文里」「文章说」「作者提到」「蓝皮书讲」「这一章」。
**读者根本不知道那篇文章存在**，一出现就暴露了「我在转述别人」，可信度和亲切感同时塌掉。

| ❌ | ✅ |
|---|---|
| 原文里有一句话说得特别清楚 | 这里有个区分特别关键 |
| 文章提到技能分三层加载 | 技能是分三层加载的 |
| 第 5 章讲的是怎么加载技能 | （直接讲怎么加载） |

完整规则（含唯一的「事实归属」例外）见 `references/人味写作规范.md` §一。

**2. 不要为了具体而编造。**

| ❌ 编造具体 | ✅ 普遍成立 |
|---|---|
| 上周你跟 AI 说过的那句话（为什么是上周？） | 同一件事，你跟 AI 说过多少遍了？ |
| 我测了 100 个工具 | （没真测就别写数字，换公式） |

**具体化只有两个合法来源：真的发生过，或者普遍成立。** 编造的时间、数量、场景是最容易露馅的 AI 味。

## 一、和图文的关系：两个版本各做各的

| | |
|---|---|
| **不要求** | 一一对应、页序一致、共用分镜 |
| **共用** | `sources/` 源材料、`templates/` 设计令牌、标题公式（`references/标题与封面规范.md`） |

**拆视频的条数不需要和图文的分页数一致。** 同一条视频和同一条图文的标题也可以不同。

## 二、目标人群：每一句都对着这个人写

> **小林**，30 岁，运营 / 行政 / HR / 销售，非技术岗。用过豆包、Kimi，但**只会当搜索框用**。
> 知道 AI 有用，不知道「我该学什么」。收藏夹里躺着十几个教程没打开。想买课又怕被割。
> 看视频的场景：通勤、午休、睡前，竖屏，**手指随时准备划走**。
> 他只有两个问题：**这跟我有什么关系？我今天能用上什么？**

| 是 | 不是 |
|---|---|
| 「我先踩完坑，讲给你听」的同行者 | 技术大神 |
| 讲一个动作，讲你会得到什么 | 讲原理，讲它有多强 |
| 用「我们」 | 用「你们」 |
| 不吹参数、不追热点、不制造焦虑 | 贩卖焦虑、蹭新闻 |

**反割韭菜**是账号的信任资产，但**不能每条都喊**——喊多了就变成人设表演。

---

## 三、长度

**单条默认 60–75s（350–435 字），硬上限 90s（520 字）。**

超过 90s 不做，**拆条**。
排稿用 **5.8 字/秒**（见文件开头的两次实测）。

**一条真实经历**：第 5 章第 1 条按 6.35 排到「预计 71.5s」，
实际出音 **78.9s** —— 多出来的 7 秒全在引号、冒号、短句停顿和场景气口上。
所以**没出音频之前，任何时长都只是估算**。

## 四、五段式结构

以 75s / 435 字为例（按 5.8 字/秒）：

| 段 | 时间轴 | 字数 | 任务 |
|---|---|---|---|
| **钩子** | 0–5s | ≤ 29 字 | 3 秒内让人不划走，末尾一个节奏标记 |
| 共鸣 | 5–18s | ~75 字 | **命名他的状态 + 修正他的归因** |
| 给答案 | 18–30s | ~70 字 | 一句话结论，**先给结论** |
| 展开 | 30–65s | ~200 字 | 2–4 个要点，**一段一个意思** |
| 收尾 | 65–75s | ~58 字 | 明确站队 + 一个提问 |

**共鸣段不是"描述他的行为"，是「命名 + 归因」：**

| 步骤 | 做什么 | 例 |
|---|---|---|
| ① 命名状态 | 把他说不清的感受说出来 | 「很多人会卡在这一问」 |
| ② 修正归因 | 告诉他**真正的**原因在哪 | 「不是不会做，而是流程乱了」 |

**修正归因是全片信息密度最高的一句**，值得为它破例用一次「不是……而是……」（见 `references/人味写作规范.md` §五 的例外条款）。

## 五、钩子：决定这条视频的生死

### 硬规则

1. ❌ 禁止铺垫型开场（先说背景、先讲定义、先做自我介绍）
2. ✅ **第一句就是冲突、后果、或反常识**
3. ✅ **口播钩子必须和封面主标题不一样** —— 封面求「点击」，口播求「停留 3 秒」，但**指向同一个命题**
4. ✅ 钩子末尾放一个 **2–4 字的节奏标记**，明确宣告进入正题（「直接开始」「先说结论」「就三件事」）。
   观众需要知道"铺垫结束了"，否则会一直等。

### 四种可直接套的开场结构

都是从真人爆款视频里拆出来的，**比空泛的「代价型」好用得多**。

| # | 结构 | 原文示例 | 要点 |
|---|---|---|---|
| 1 | **条件式后果** | 使用 Codex 的时候，**如果不改这几个设置**，它很容易变成话多费 token、没跑几个任务就消耗一大半的 agent | 触发条件 + **把恶果具象化**（不是"效果不好"，是"话多、费 token、跑一半就没了"） |
| 2 | **收益带数字** | 这一期可以帮你**降低 80%** 的 token 消耗 | 收益端也要有具体数字，不能只说"讲清楚" |
| 3 | **门槛拆除** | 首先就**四个**基础设置，**一分钟**就能设置完 | 钩子末尾立刻拆掉"这很难"的心理门槛 |
| 4 | **提问代入** | 如果现在让你马上做一条视频，你脑子里的**第一步是什么**？ | 提问必须能让观众**在心里立刻给出一个答案**（哪怕是"不知道"）。问完就接「很多人会卡在这一问」 |

**组合用法**（推荐）：4 → 停顿 → 1 → 2 → 3 → 节奏标记。
先让观众在心里作答，再告诉他"你卡住不是你的错"，然后给后果、给收益、拆门槛，最后宣布开始。

### 三种语气形态（和上面四种结构正交，可叠加）

| 形态 | 结构 | 例 |
|---|---|---|
| 代价型 | 你为这个错误付了多少时间 / 钱 | 同一件事，你跟 AI 说过多少遍？ |
| 反常识型 | 你以为 A，其实 B | AI 记不住你，问题不在提示词 |
| 场景代入型 | 复述他**普遍会做**的那件事 | 换个对话，就得从头再教一遍 |

### ⚠️ 提问式的两个前提

1. **普遍成立**，不能编造具体时间（❌「上周你跟 AI 说过的那句话」——为什么是上周？）
2. 问完**立刻接一个诊断**：「很多人会卡在这一问，不是不会做，而是流程乱了」

### 自我介绍：看账号阶段，不是一刀切

| 阶段 | 做法 |
|---|---|
| **新号（当前）** | ❌ **不放**。没有认知度，说了也白烧 3 秒 |
| 有粉丝基础后 | 可放 **≤ 4 字的称呼**，且必须**紧跟钩子**，不能单独占一拍 |

> 「嗨，我是露露」能成立，是因为**"露露"本身已经是识别信号**。新号没有这个资产，照抄只会浪费开头。

> **称呼与阶段以 `references/账号定位规范.md` §八 为准**（当前：新号不放；有认知度后用 `Kai`）。三处规则必须一致。

## 六、语言规范

| 规则 | 说明 |
|---|---|
| 单句 ≤ 25 字 | 超了就断句 |
| 数字口语化 | 说「三个」不说「3个」；「2026」念「二零二六」 |
| 不念代码 | 代码块、文件树、报错信息一律不进嘴 |
| 不念表格 | 表格是好画面，不是好台词——**翻译成人话再说** |

**禁词与禁句式**：完整列表见 `references/人味写作规范.md` §五（AI 习语 / AI 句式 / 互联网黑话）。

口播稿额外一条：**写完必须念一遍。** 念着别扭的地方就是 AI 味，改到顺口为止。

## 七、术语念法表

**小白听不懂英文术语。默认全部读中文。**

| 书面 | 口播怎么念 | 备注 |
|---|---|---|
| Skill | **技能** | 全片第一次出现时补一次「也就是 Skill」 |
| Prompt | **提示词** | |
| Agent | **智能体** | |
| WorkBuddy | **读英文 WorkBuddy** | 产品名，读中文指代不清 |
| MCP / API / CLI | **尽量避免**；必须出现时念字母 | 出现即解释一句它是干什么的 |

## 八、分段 = 分镜（这条最省事）

口播稿**按段写**，每段前面标一行分镜信息：

```
【场景 3 · 约 12s · 画面：对比页 · 用图：原文图 05】
```

- 场景时长 = **该段字数 ÷ 6.35**，写完自己算一遍填进去
- 画面类型用现有页型名（封面 / 痛点 / 概念 / 对比 / 清单 / 步骤 / 截图 / 收尾）
- 用图：写明用哪张原文配图；**不用图就写「无图」**
- **用户审口播稿的时候，等于同时把分镜审了**，不需要再单独过一遍分镜表

---

## 九、收尾

必须同时有两样，缺一个就是烂尾：

1. **一句明确站队** —— 说「我的判断是……」，不说「看情况」「因人而异」
2. **一个具体提问** —— 提问必须能让评论区真的答得上来（问经历，不问观点）

❌ 不收尾于「希望对你有帮助」「记得点赞关注」。
❌ 不做关注引导（小红书对硬引导敏感，靠内容留人）。

---

## 十、一篇文章拆几条视频

**判断顺序：**

1. **先算「可口播字数」** —— 剔除代码块、文件树、纯操作步骤（念出来没人听得懂）
2. **切点必须落在「独立知识点」的边界上**，**绝不按字数平均切**
3. **每条必须能独立看懂**：完整的钩子 → 答案 → 收尾
4. 🚫 **禁止「上集 / 下集」** —— 小红书是推荐流，观众刷不到下集，「下集」两个字直接杀死完播率。**系列感靠选题角度体现，不靠「第X集」。**
5. 判断方法：先列「独立知识点清单」→ 每个知识点**能不能撑起 380 字**？能就一条，不能就**合并相邻知识点**

**不适合做视频的内容**：安装、下载、点按钮、导入导出这类「照着点」的操作流程——卡片化的信息量太低，**留给图文**。

## 十一、出稿前自查

- [ ] **有没有出现「原文」「文章说」「作者」「这一章」？有就整段重写**
- [ ] **有没有为了具体而编造时间 / 数量 / 场景？**
- [ ] 前 3 秒有没有出现「大家好」或铺垫？
- [ ] 钩子和封面主标题是不是两条不同的话？
- [ ] 字数 ÷ 5.8 是不是落在 60–75s？（**以出音后的 ffprobe 实测为准**，估算不算数）
- [ ] 有没有超过 25 字的句子？
- [ ] 有没有出现禁词、禁句式？
- [ ] 英文术语是不是都按念法表处理了？
- [ ] 表格 / 代码有没有被直接念出来？
- [ ] 每段前面有没有分镜标注？
- [ ] 结尾是不是「明确站队 + 一个具体提问」？
- [ ] 是不是能独立看懂，不需要看「上一条」？
