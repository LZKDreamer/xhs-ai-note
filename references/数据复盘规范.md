# 数据复盘规范

> **解决什么问题**：目前所有规则都来自「踩坑教训」，缺**正向验证**通道——
> 哪种标题公式真的带来点击？哪个搜索词真的带来流量？没有数据回流，规范永远无法自我进化。
> **配套文件**：`数据记录表.md`、`爆款标题档案.md`（仓库根目录，持续回填的活文档）。

---

## 一、记录什么（每条笔记，24h / 72h 各回填一次）

`数据记录表.md` 每行一条：

```markdown
| 发布日期 | 笔记 | 目标搜索词 | 标题公式 | 24h曝光 | 24h点赞 | 24h收藏 | 24h评论 | 72h收藏 | 收藏率 | 搜索流量占比 | 涨粉 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 2026-10-15 | x-01 开源AI内容系统 | AI自动写稿 | 反转结论 | | | | | | | | |
```

- **收藏率 = 收藏 ÷ 曝光**——知识号的核心 KPI（账号定位规范 §七），比点赞重要
- **搜索流量占比**在创作者中心「笔记诊断」里看——验证搜索词卡位是否成功
- 涨粉只作参考，不作为判断依据（前 20 篇天然低，这是定位决定的）

## 二、每周复盘（30 分钟，回答三个问题）

1. **哪个标题公式数据最好？** → 把标题 + 24h 数据抄进 `爆款标题档案.md`，公式库用真实数据迭代，不永远靠初始假设
2. **哪个搜索词带来了流量？** → 同词再排 1 条进 `选题库.md`（选题库规范 §三）
3. **收藏率最高的一条做对了什么？** → 能带走的页是什么形态？复用该页型

`爆款标题档案.md` 格式：

```markdown
| 日期 | 标题 | 公式 | 24h曝光 | 收藏率 | 备注（做对了什么） |
|---|---|---|---|---|---|
```

## 三、数据怎么反哺规范（闭环的最后一公里）

| 发现 | 动作 |
|---|---|
| 某公式连续 3 条数据好 | 在 `references/标题与封面规范.md` 该公式旁标注「实测有效 + 日期」 |
| 某公式连续 3 条数据差 | 降为备选，标注「实测偏弱 + 日期」 |
| 某搜索词带来稳定流量 | 这个词的选题在 `选题库.md` 里优先级上调 |
| 某页型收藏率明显高 | 在 SKILL.md 第 2 步分页表里标注「优先用」 |

> **原则**：规范里每一条「经验」，最终都要么来自踩坑，要么来自数据——不允许永远停留在假设。
