## 一、核心策略调整

| 维度 | Skill 输出 | 我的重写 | 理由 |
|---|---|---|---|
| 页数 | 9 页 | **7 页** | 减少滑动疲劳，提高完读率 |
| 截图页 | 4 页（占 44%） | **2 页**（占 28%） | 截图是"减速带"，太多会打断阅读流 |
| 情绪曲线 | 平稳递进 | **过山车式**：痛点炸裂 → 希望升起 → 爽点验证 → 行动召唤 | 小红书爆款需要情绪起伏 |
| 封面公式 | 反转结论 | **数字锚定 + 反转结论** | 数字是注意力的第一触点 |
| 金句设计 | 无独立金句页 | **新增独立金句页** | 可截图传播，带来二次传播 |
| 互动钩子 | "评论区聊聊" | **让评论区"吵起来"** | 争议性提问比开放式提问互动率高 3-5 倍 |

### 已选（主标题）

**公式映射**：
```text
公式: 资历背书 + 痛点动作 + 解决方案
骨架: [数字资历] + [核心痛点] + [交给AI]
标题片段: 2000个公众号之后，他把找素材这活交给了AI
数字锚: 2000（运营过的公众号数量，真实不编造）
痛点: 找素材（原文反复出现的高频痛点）
主体: 程序员/运营者（身份标签，吸引同类人群）
出处: 原文第116行「运营2000多个公众账号」+ 全文核心命题
```

**为什么比原版的「写稿一小时，最累的却是找素材」更好**：
- 原版是**纯痛点标题**，没有给读者"这跟我有什么关系"的锚点
- 新版用「2000个公众号」建立了**资历信任**，读者会想"运营过2000个号的人都被这个问题困扰，那我的困扰是合理的"
- 「交给了AI」给出了**解决方向**，不是纯诉苦，是希望感

## 三、正文（可直接复制发布）

> 标题就是下面第一行

**2000 个公众号之后，他把找素材这活交给了 AI**

做内容的，有没有算过一笔账？

你每天花多少时间在"找"上？找素材、找选题、找角度……一天下来，真正用来写的时间，连三分之一都不到。

有个叫猫哥的程序员，运营过 2000+ 公众号。他把这套「机械重复」的活，做成了一个开源系统，叫 **ai-content**。

现在 GitHub 上已经有 **200+ star**。

---

**它替你做五件事，全程不用人盯着：**

1️⃣ **定时收素材** 📥
配好信息源（RSS/API/网页都行），系统自动按计划收进同一个库，来源、链接、采集时间全记着——你再也不用翻十几个平台的收藏夹。

2️⃣ **AI 挖选题** 🤖
从素材里自动提炼候选题，从 5 个维度打分：内容价值 / 情绪价值 / 全网声量 / 降维科普 / 画像贴合。评分低的直接筛掉，不用你自己一条条翻。

3️⃣ **按定位精准匹配** 🎯
同一个热点，AI 工具的号和副业的号，切口完全不同。系统按你写的定位自动匹配——定位写得越准，选题越对味。

4️⃣ **按你的风格出稿** ✍️
调你配置的模型、提示词、文章模板，自动生成初稿。甚至能做小红书笔记——卡片风格都给你做好了，下载就能用。

5️⃣ **定时出稿，门槛卡死** ⏰
可设最低评分门槛、单次最大篇数。比如低于 90 分的不处理，单次最多出 2 篇——避免一口气堆几十篇等你审。

---

**最让我 respect 的两个细节：**

✅ 他不编「效率提升 10 倍」这种数字
每个人的信息源和审核标准不同，省多少自己跑一阵才知道。

✅ 出稿后还坚持人工核验
涉及收入、效果、产品能力的句子，全部重新看一遍——不盲目发。

---

**⚠️ 但门槛先说在前头：**

这套系统需要自己部署（数据库 + Redis + 模型服务）。如果你完全不懂技术，搭起来确实不轻松。

**但下面这 3 件事，任何人都能直接抄：**

1. **信源固定好**——你喂它什么，它就能挖出什么
2. **定位写准**——这是实打实的输入，写不准选题就是散的
3. **出稿前一定核验**——别当甩手掌柜，AI 写的也要过一遍人眼

---

**最后送一句话：**

> 把重复的收集和起稿交出去，把判断和表达留给自己。

你每天那段「完全机械、但必须做」的活——就是最该交给 AI 的地方。

## 六、图片里的文案优化点

### Skill 版图片文案的问题

1. **封面主标题字号不够大**：在信息流缩略图中，"写稿一小时"可能看不清
2. **痛点页太平**：4 个灰色气泡均匀排列，没有视觉焦点，冲击力弱
3. **步骤页信息密度低**：5 步各占一行，页面下方有大片空白，浪费注意力
4. **截图页 eyebrow 太小**："ai-content · 工作台"在手机上可能看不清
5. **清单页标题太长**："三件可以直接抄 一件必须知道"——两行标题压缩了内容空间
6. **收尾页没有视觉锚点**：纯文字，滑动到最后一页没有"停住"的理由

### 我的优化方案

1. **封面**：数字"2000"用最大字号（占页面宽度 80%），其次是"找素材"，形成视觉层级
2. **痛点页**：用深色底（#2C2C2A）+ 白色文字，与前后页形成强烈对比；4 个痛点用不同字号制造节奏
3. **步骤页**：5 步用横向时间轴而非纵向列表，节省纵向空间
4. **截图页**：eyebrow 字号放大 20%，截图本身用画框+投影突出
5. **金句页**：整页只放一句话，字号占页面 60%，最大化传播力
6. **收尾页**：用争议性提问作为大字标题，制造"必须停下来看"的冲突感

## 七、关于视频口播稿

> 注：原 Skill 输出中没有包含视频口播稿。如果后续需要生成口播稿，建议按以下思路设计。

### 口播稿与图文的差异

| | 图文笔记 | 视频口播 |
|---|---|---|
| 信息载体 | 文字 + 图片（可回看） | 声音 + 画面（一次过） |
| 用户耐心 | 可滑动回看 | 3 秒定生死 |
| 钩子设计 | 封面标题 | 第一句口播 |
| 结构 | 9 页可承载更多信息 | 60-75s，只能讲 1 个核心命题 |
| 截图 | 4 张截图详细展示 | 口播中念不出界面细节，需要翻译成人话 |

### 如果为 ai-content 做口播稿

**拆条建议**：
- 条 1：「找素材比写稿更耗时间」（纯痛点+解决方案，不讲技术细节）
- 条 2：「AI 怎么给选题打分」（五维评分机制，反常识钩子）
- 条 3：「90 分门槛」（门槛设计的思维，争议性话题）

**钩子示例（条 1）**：
> 【场景 1 · 钩子】
> "做内容的，有没有算过一笔账？
> 你每天花多少时间在『找』上？
> 直接开始。"

**注意**：
- 口播稿第一句 ≤ 17 字，必须是完整单句
- 不出现「原文」「文章说」「作者」等解读视角
- 原文中的具体数字（2000+ 公众号、200+ star、1431 条素材）优先保留
- 结尾：一句话总结 + 明确站队 + 具体提问

## 八、总结：Skill 是否需要修改优化？

### 结论：需要优化，具体建议如下

| 优先级 | 优化项 | 问题 | 建议 |
|---|---|---|---|
| P0 | **标题公式库** | 当前只用「反转结论」，缺少「数字锚定」「资历背书」等更吸睛的公式 | 增加 3-5 个爆款标题公式，根据内容类型自动匹配 |
| P0 | **页数控制** | 默认 9 页，截图页过多 | 增加「页数策略」参数：精简版（5-7 页）/ 完整版（9 页），根据内容类型推荐 |
| P1 | **情绪曲线设计** | 当前情绪曲线偏平，没有明显的起伏 | 增加「情绪节奏」模块：痛点页用深色底、金句页独立、收尾用争议性提问 |
| P1 | **金句页生成** | 当前没有独立金句页 | 增加「金句提炼」步骤：从正文中提取一句话，独立成页，最大化传播力 |
| P1 | **互动钩子优化** | 当前用"评论区聊聊"等开放式提问 | 增加「争议性提问」模板：让评论区"吵起来"，提高评论率 |
| P2 | **正文风格** | 当前正文有模板化表达（"家人们谁懂啊"） | 增加「去模板化」检查：避免过度使用已被滥用的开场 |
| P2 | **口播稿联动** | 当前图文和口播稿没有联动机制 | 如果检测到视频需求，自动生成拆条方案和口播稿大纲 |

### 一句话评价

> Skill 输出的图文笔记在**结构完整性、设计统一性、来源合规性**上做得非常好，但在**爆款吸引力**上还有提升空间——标题缺数字锚点、情绪曲线偏平、缺少可传播的金句页、互动设计偏弱。优化后，点击率、完读率、互动率预计可提升 20-40%。
